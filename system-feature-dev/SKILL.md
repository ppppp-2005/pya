# 系统功能开发

使用这个技能时，不要一上来直接写代码。先把功能放进现有系统语境里，按阶段推进，必要时再实现。

## 7 阶段流程

1. **需求确认**
   - 说明用户要解决的问题、目标用户、输入输出、权限、数据、边界情况。
   - 如果需求会影响架构，先问最多 3 个关键问题。
   - 对简单任务可以做合理假设，并明确写出来。

2. **代码库理解**
   - 搜索类似功能、入口文件、控制器、服务层、数据访问层、配置和测试。
   - 总结现有分层、命名、错误处理、数据库访问、接口风格。
   - 给出必须阅读或修改的关键文件。

3. **方案设计**
   - 给出模块划分、数据流、接口、数据库变更、异常处理和测试点。
   - 对复杂功能至少比较两种方案：最小改动方案和更清晰的架构方案。
   - 推荐一个方案，并说明为什么适合当前项目。

4. **实现计划**
   - 列出要新增或修改的文件。
   - 按最小可运行版本排序：模型/表结构、接口、业务逻辑、UI、测试、文档。
   - 标明风险点，例如兼容性、事务、安全、并发、性能。

5. **编码实现**
   - 遵守项目已有风格和语言规范。
   - 保持改动范围集中，不做无关重构。
   - 对关键逻辑加必要注释，避免解释显而易见的代码。

6. **验证与质量复核**
   - 运行可用的编译、测试、格式化或静态检查命令。
   - 检查错误处理、空值、边界条件、权限、数据一致性和测试缺口。
   - 发现问题后先修复高风险问题，再处理可选优化。

7. **交付总结**
   - 总结完成的功能、关键设计决定、修改文件、验证结果。
   - 给出适合写进毕业论文或项目报告的系统实现描述。

## 输出要求

- 面向中文用户时使用中文。
- 做毕业设计系统时，说明要能转化为“需求分析、系统设计、详细实现、系统测试”章节。
- 写代码前先给结构，写完代码后必须给验证结果。
