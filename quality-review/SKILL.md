# 质量复核

使用这个技能对已经写好的代码做高信号检查。优先找会影响功能、稳定性、安全和可维护性的真实问题。

## 检查重点

1. **功能正确性**
   - 空值、越界、异常路径、状态不一致、错误分支。
   - 异步、并发、事务、资源释放和生命周期问题。

2. **异常处理**
   - 是否吞掉错误。
   - 错误信息是否清楚、可定位、可恢复。
   - fallback 是否会隐藏真实问题。

3. **测试缺口**
   - 核心业务路径是否有测试。
   - 边界条件、失败场景、权限场景是否覆盖。
   - 测试是否验证行为，而不是过度绑定实现细节。

4. **安全性**
   - SQL/命令注入、XSS、路径穿越、反序列化风险。
   - 硬编码密钥、权限绕过、敏感数据泄露。

5. **可维护性**
   - 重复代码、过深嵌套、过大函数、职责混乱。
   - 类型设计是否能表达业务约束。
   - 命名和项目风格是否一致。

## 输出格式

按严重程度排序：

- **严重问题**：必须修复，否则会导致错误、安全风险或数据问题。
- **重要问题**：建议修复，会影响维护、测试或用户体验。
- **改进建议**：可选优化。

每条问题都要包含：

- 文件和行号（如果能定位）
- 问题说明
- 为什么重要
- 具体修改建议

如果没有发现高信号问题，明确说明“未发现必须修复的问题”，并列出剩余风险或未运行的测试。
